# SkyLine 航空客运订票系统 — 课程设计总结

> **课程**: 数据结构与算法课程设计 | **版本**: v2.3 | **日期**: 2026-06-18

---

本次课程设计实现了一个功能完整的航空客运订票系统（SkyLine），项目约 3,500 行代码，采用 HTML5 + CSS3 + 原生 JavaScript（零外部依赖），分四层架构：数据层（链表/队列）、业务层（订票/退票/搜索）、展示层（DOM 交互）和样式层（CSS 视觉）。系统完成了航线录入、航班查询、客票预订与候补、退票及候补自动补位等全部基本功能，并扩展实现了可视化座位图（三舱分区、液态玻璃机身）、高级多维筛选、多乘客跨舱位选座、旅客类型差异化折扣、PNR 追踪、数据导入导出等。

程序设计过程中最大的收获是将课堂上学到的抽象数据结构落地为可运行代码时的细节处理。例如，按姓名排序的单链表在 JavaScript 中使用 `localeCompare(name, 'zh')` 才能正确完成中文拼音排序；链式队列的 `front` 和 `rear` 双指针在出队时需要同步处理队列变空的边界情况；`localStorage` 序列化要求将链表/队列转换为纯 JSON 数组，反序列化时重建所有 `next` 指针和引用关系。这些细节在课堂理论中不会涉及，却是实际编码中决定正确性的关键。遇到的主要问题包括：退票候补补位的公平性策略——最初只要有票就分配，可能跳过队头需求量大的人，改为"全有或全无"（队头需求 ≤ 余票才分配，否则保持队列顺序）后才符合 FIFO 公平原则；座位图从"左驱右"（表单选舱位再自动分配座位）重构为"右驱左"（点击座位直接多选，表单自动跟随切换）交互模式时，需要准确维护 `seatCabinMap` 映射，避免从 DOM 反查导致数据不一致；多乘客订票的原子性——预校验全部通过后才逐人提交，任一失败立即终止并汇报部分成功状态。

调试方面，我体会到分层隔离调试的有效性——数据层用 `console.table()` 检查链表结构，业务层在浏览器 Console 直接调用方法验证返回值，UI 层通过 DevTools 追踪 DOM 状态和事件绑定。最隐蔽的 bug 往往来自持久化层：旧版本 `localStorage` 数据格式与新代码不兼容，需要清理或回退。两个典型调试案例令我印象深刻：链式队列 `enqueue()` 漏写 `rear = node` 导致连续入队后只保留一个节点，排查方法是逐步 `console.log` 双指针状态；座位图价格显示错误源于从 DOM class 反向推断舱位（动画期间 class 不可靠），最终改为渲染时同步构建纯 JS 映射对象解决。这些经历让我认识到，调试不是盲目试错，而是先形成假设再有目的地验证，追踪关键数据在操作前后的变化往往比逐行阅读代码更高效。

本次课程设计全程使用 Claude Code（集成于 VS Code 的 AI 编程助手）作为辅助工具。它贯穿了四个开发阶段：初始搭建时根据设计要求生成数据结构和核心业务逻辑框架；UI 开发阶段辅助编写事件绑定和 CSS 样式体系（包括 Premium 航司主题和响应式布局）；可视化座位图阶段协助设计三舱分区算法和液态玻璃 CSS 效果；迭代阶段支持高级搜索、多乘客订票等扩展功能。效率提升显著的场景包括 CSS 编写（描述视觉效果即可生成，约 3-5 倍提速）、重复性代码批量生成（约 3-4 倍）、文档撰写（约 5-10 倍）以及跨文件重构（约 5-8 倍）。但 AI 也有明显局限：项目超过 3,000 行后无法在单次对话中完整理解全部代码，需要拆分为独立模块；生成代码的语法正确但业务逻辑需人工验证——例如候补补位策略最初被生成为"跳过队头直接分配"，经我指出后才修正；CSS 视觉效果的精细调优（`border-radius`、`backdrop-filter`、阴影层次）AI 无法直接"看到"，必须人工反复调整。我总结的最有效协作模式是"人做设计决策 → AI 做代码执行 → 人做质量审查"——AI 是高效协作者而非替代者，真正的能力体现在"知道要生成什么"和"判断生成的对不对"上。

对于课程本身，我有三点建议。第一，在数据结构选择的教学中增加"为什么这样选"的工程权衡讨论——例如已订票名单为何用链表而非数组（频繁插入删除）、候补队列为何用链式而非 `push/shift`（O(n) 复杂度），帮助学生在"完成规定动作"之外理解设计决策背后的原因。第二，建议明确制定 AI 工具使用政策——当前 AI 编程工具已非常普及，与其简单禁止或默许，不如将其纳入教学内容（如专门讨论如何有效与 AI 协作编程、如何验证 AI 生成代码的正确性），并相应调整考核方式（增加设计文档质量、口头答辩、边界测试设计等维度），因为当 AI 可以生成代码时，真正的能力体现在"知道要生成什么"和"判断它对不对"。第三，航空订票系统这类贴近实际业务场景的选题很好，建议保持并增设扩展加分项（往返搜索、服务端存储、无障碍支持等），鼓励学有余力的学生深入探索，让数据结构不再是孤立的理论，而是解决实际问题的工具。
