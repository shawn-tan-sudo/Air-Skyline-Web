SkyLine 航空客运订票系统 需求分析
版本 v2.2  更新时间 2026年6月16日
一、项目概述
SkyLine 是一个纯前端的航空客运订票系统，使用 HTML、CSS 和原生 JavaScript 开发，无需任何外部依赖，直接在浏览器中打开即可运行。系统围绕三条核心数据结构展开：航线汇总表使用顺序存储（数组，按航班号有序排列），已订票客户名单使用按姓名排序的单链表，候补客户名单使用链式队列（先进先出）。数据通过浏览器 localStorage 持久化存储。
系统分为四层架构：数据层（data-structures.js）、业务层（airline-system.js）、展示层（index.html 和 app.js）、样式层（style.css）。各层之间有严格的依赖顺序：数据层无依赖，业务层依赖数据层，展示层依赖前两者。
二、数据层 data-structures.js
该模块提供纯数据结构，不包含任何业务逻辑，被业务层调用。包含四个类。
CustomerNode（已订票客户节点）：存储单个已订票客户的完整信息，包括姓名、订票数量、舱位等级（1表示头等舱、2表示商务舱、3表示经济舱）、分配的座位号数组、PNR订票参考号、订票时间、旅客类型（成人、儿童、婴儿）、联系方式。节点持有 next 指针，支持单向链表遍历。
SortedLinkedList（按姓名排序的已订票客户链表）：这是系统中最核心的数据结构之一，每个航班持有一个实例。新客户插入时使用 localeCompare 做中文拼音排序，始终维持链表有序性。支持按姓名查找和删除节点，也支持按 PNR 参考号查找和删除节点（用于退票和订单查询）。提供统计总订票数的功能（遍历累加所有节点的 ticketCount），以及将链表序列化为纯对象数组的功能（供 localStorage 持久化使用）。
WaitNode（候补客户队列节点）：存储候补客户的姓名、所需票数、舱位偏好、联系方式，入队时自动记录入队时间。持有 next 指针用于链式队列。
LinkedQueue（候补客户链式队列）：实现先进先出的链式队列，每个航班持有一个实例。维护 front（队头）和 rear（队尾）双指针。支持在队尾追加新节点（enqueue）、从队头移除节点（dequeue）、查看队头节点但不移除（peek，用于退票自动补位时判断队头需求是否可满足）、按姓名遍历删除（removeByName，用于候补取消场景）、判空与计数、序列化为含位置序号的数组。
三、业务层 airline-system.js
业务层封装了所有航空订票的核心逻辑，包含 Flight 类和 AirlineSystem 类。
Flight 类（航线记录）：每条航线记录包含始发站及三字码（如北京 PEK）、终点站及三字码（如上海 SHA）、航班号（如 CA1001）、飞机号及机型（如 B787 9）、飞行日期（YYYY MM DD 格式）、起飞时刻与到达时刻（HH:MM 格式）、乘员定额、三级舱位票价（头等舱、商务舱、经济舱）。
余票管理：remaining 字段跟踪可售票数，提供 isFull 和 bookedCount 两个计算属性。
座位自动分配（generateSeatNumbers）：基于已售票数起点，按每排6座（A到F列）顺序生成座位号，格式为排号加列字母，如 1A、1B。
已占用座位查询（occupiedSeats）：遍历已订票链表，收集所有已分配的座位号，返回 Set 集合。
可视化座位图生成（getSeatMap）：这是座位图的核心数据源，按三舱分区。头等舱为第1至2排，采用1 2 1布局（A、C两列，中间过道，D、F两列），超大间距。商务舱为第3至5排，采用2 2布局。经济舱从第6排起，采用3 3布局（A、B、C三列，中间过道，D、E、F三列）。经济舱第1排和第11排标记为紧急出口排。每个座位标记三个特征：window 表示靠窗（A或F列）、aisle 表示过道（C或D列）、extra_legroom 表示额外腿部空间（出口排）。
票价查询（getPrice）：按舱位等级返回对应票价，默认回退到经济舱票价。
AirlineSystem 类（系统主控）：这是整个系统的核心控制器，管理所有航班的增删改查和订退票流程。
航班管理方面，addFlight 方法按航班号有序插入 flights 数组（顺序存储结构），使用 findIndex 加 splice 维持有序性，操作后自动持久化。findFlight 方法按航班号顺序搜索返回 Flight 对象。getAirports 方法去重返回所有始发站和终点站列表（含三字码），用于填充搜索下拉菜单。
PNR 生成方面，_generatePNR 方法生成6位唯一 PNR 参考号，字符集包含字母和数字但排除易混淆的 I、O、0、1。通过 _pnrExists 方法遍历所有航班的已订票链表确保全局唯一性。
航线搜索（searchFlights）支持按始发站和终点站模糊匹配，可选按飞行日期精确过滤。日期未指定或指定日期无匹配时返回所有匹配航线的航班。返回结果包含航班号、机型、航线信息、飞行日期、时刻、运力、余票、满员状态、各舱位票价、候补队列人数。
订票流程（bookTicket）是系统最核心的功能，流程为：查找航班并验证存在性，验证订票数量必须大于零，检查同一航班同一姓名不能重复订票，判断余票是否充足。余票充足时生成唯一 PNR，分配座位（支持手动选座或自动分配），插入已订票链表，扣减余票，持久化。手动选座模式会验证座位数量是否匹配且未被占用。价格计算方面，旅客类型折扣乘数为成人 1.0、儿童 0.75、婴儿 0.1。跨舱位选座时按每座实际舱位独立计价，普通模式按统一舱位乘以数量乘以类型乘数计算。返回结果包含 PNR、座位号、舱位信息、票数、总价、旅客类型、折扣乘数、航班详情等。余票不足时返回 canWaitlist 为 true，引导用户进入候补流程。
加入候补（joinWaitlist）：验重后（同一航班同一姓名不能重复候补）将客户加入候补队列，返回排队位置。
退票流程含候补自动补位：支持按姓名退票（refundTicket）和按 PNR 退票（refundByPNR，推荐方式）。lookupByPNR 方法全局搜索 PNR 返回完整订票详情，价格已含旅客类型折扣。_processRefund 是退票核心处理方法：从已订票链表删除客户节点并释放票额，然后进入 while 循环处理候补队列——查看队头，若队头需求票数不超过当前余票则出队、生成新 PNR、自动分配座位、插入已订票链表、扣减余票，否则停止（保持队列原有顺序）。
统计与持久化：stats 方法统计航线总数、总运力、总已售、总剩余、候补总人数。_persist 方法将 flights 数组序列化为 JSON 存入 localStorage（键名 airline_v2_data），包含每条航班的完整信息及已订票链表和候补队列的数据快照。load 方法从 localStorage 反序列化数据并重建所有对象和链表结构。clearAll 清空所有数据。initTestData 初始化17条测试航线，覆盖北京、上海、广州三大枢纽，含各主流机型，并预置部分订票和候补数据用于演示。
四、展示层 index.html 和 app.js
全局布局：Header 区域左侧为品牌标识（Air SkyLine，Premium Booking Experience），右侧实时显示三项核心统计指标——航线数量、可订座位总数、候补旅客总人数。Tab 导航栏包含5个标签按钮，通过 data tab 属性关联对应内容区。页面底部有 Toast 通知容器，支持成功、警告、错误、信息四种消息类型。
五个 Tab 页面功能如下。
Tab 1 航班总览（tab overview）：Hero 快捷搜索区采用深色渐变背景，输入出发城市和到达城市（支持 datalist 机场建议，可选出发日期），一键搜索航班。全部航线汇总表展示所有航班的航班号、航线、机型、飞行日期、起降时刻、运力、余票、状态标签（有票、仅剩若干座、满员、候补人数）和操作按钮。点击行可展开详情，显示该航班的已订票客户子表（含姓名、票数、舱位、座位、PNR、旅客类型）和候补队列子表（含序号、姓名、需票、舱位偏好、联系方式、登记时间）。底部有恢复测试数据按钮，可一键重置为初始数据。
Tab 2 搜索航班（tab search）：高级搜索表单通过下拉菜单选择始发站和终点站（含三字码），可选出发日期。搜索结果包含排序控件，支持8种排序方式——默认顺序、头等舱价格升序和降序、商务舱价格升序和降序、经济舱价格升序和降序、起飞时间从早到晚和从晚到早。每行结果显示三舱票价和余票状态。有票时提供预订按钮（自动跳转订票 Tab 并选中航班），满员时提供候补按钮（弹窗收集姓名和票数）。
Tab 3 预订客票（tab book）采用三步流程。步骤一选择航班：下拉菜单显示航班号、航线、飞行日期和余票，确认后展示航班预览卡片并解锁步骤二。步骤二旅客信息与选座采用左右双栏布局，左侧为旅客表单区域，右侧为可视化座位图。表单支持双模式：未选座时为单选模式，统一填写姓名、旅客类型（成人、儿童、婴儿）、订票数量、舱位等级；选座后自动切换为多乘客模式，每个已选座位生成独立行，包含座位徽章（按舱位着色）、舱位票价标签、姓名输入框、旅客类型选择下拉。顶部有舱位汇总条显示已选座位数和各舱位数量分布。座位图采用液态玻璃机身设计，三舱分区颜色标识（金色头等舱、蓝灰色商务舱、绿色经济舱），梯形 3D 座位带 hover 弹起动画，过道有分隔标记，紧急出口排高亮显示。每个可用座位标记特征圆点：蓝色表示靠窗、紫色表示过道、橙色表示额外腿部空间。鼠标悬停显示 tooltip 含座位号、舱位、票价和特征文字。系统采用右驱左交互模式：座位图是主控方，点击座位直接选中（不限数量和舱位），左侧表单自动跟随切换模式和刷新数据。取消选中同理。实时价格计算方面，多选模式按每座实际舱位乘以该座旅客类型折扣独立计价，单选模式按统一舱位乘以数量乘以类型折扣计算，座位图上方显示价格摘要栏。多乘客表单容器上通过事件委托监听旅客类型下拉变化自动刷新总价。步骤三确认预订：单选模式显示单张 PNR 确认卡（金色登机牌风格，含完整订单详情：旅客姓名、航班号、航线、飞行日期、起降时刻、舱位、座位号、票数、总价、PNR 参考号、订票时间）。多选模式显示每位旅客独立 PNR 卡片并汇总总价。余票不足时引导用户加入候补队列。
Tab 4 订单管理（tab manage）包含三个功能区。PNR 查询与退票：输入6位 PNR 参考号查询完整订单详情（含折扣后票价，非成人旅客标注折扣价字样），查到后显示退票按钮。退票确认后显示结果，含候补队列自动补位的详细信息（哪些候补客户成功补位、获得的新 PNR）。按航班加姓名退票：选择航班后联动加载该航班已订票客户下拉菜单，选择客户姓名确认退票。候补队列查询：选择航班查看完整候补队列，按队头优先顺序排列。
Tab 5 录入航班（tab add）：完整录入表单包含航班号、始发站及三字码、终点站及三字码、飞机号及机型、飞行日期（日期选择器）、起飞和到达时刻（时间选择器）、乘员定额、三级舱位票价。验证规则为始发站、终点站、航班号、飞机号必填，乘员定额必须大于零，航班号不能与已有航班重复。三字码未填写时自动取城市名前三个字符转大写。录入成功后显示确认信息、清空表单、刷新全部界面。
前端交互逻辑方面，初始化流程为：DOMContentLoaded 事件触发后尝试从 localStorage 加载已有数据，若加载失败则调用 initTestData 初始化测试航线，然后初始化 Tab 切换事件、绑定所有按钮事件、填充机场建议列表、刷新全部界面。Tab 切换时触发对应 Tab 的数据刷新，如切换到搜索 Tab 时填充机场下拉，切换到订票 Tab 时填充航班下拉并重置预订状态。
全局工具函数包括：$ 函数（document.querySelector 的简写）、esc 函数（HTML 转义防止 XSS 攻击）、passengerTypeName 函数（旅客类型枚举值转中文名称）、switchTab 函数（编程式 Tab 切换）、toast 函数（3秒自动消失的消息通知）。
五、样式层 style.css
设计语言参考阿联酋航空、卡塔尔航空、新加坡航空的高端视觉风格。主色调为深邃午夜蓝和香槟金。背景采用多层径向渐变模拟柔光效果。卡片使用白色磨砂玻璃质感。圆角体系为 8px 小圆角、14px 标准圆角、20px 大圆角、980px 胶囊圆角。通过 CSS 变量体系统一管理颜色、阴影、圆角和过渡动画参数。
座位图是样式最复杂的组件。机身外框通过 border radius 模拟机头渐窄和机尾收拢。三级舱位分区各自使用独立的配色方案（头等暖金色、商务冷蓝灰色、经济清新绿色）。座位采用梯形造型加 3D 渐变模拟座垫凹凸，hover 时缩放弹起。紧急出口排有橙色标记和背景高亮。座位特征点使用 5px 圆点指示器，三色区分特征类型。
PNR 卡片采用金色虚线边框模拟登机牌风格。多乘客表单使用柔性行布局，座位徽章按三舱着色。布局采用基础 Grid 和 Flex 自适应，移动端可折叠为单列。
六、数据结构对应关系
航线汇总表使用数组实现，按航班号有序排列，每次插入新航班时通过 findIndex 加 splice 维护有序性。已订票客户名单使用按姓名排序的单链表，挂载在每个航班实例上，新客户插入时按中文拼音排序找到正确位置，支持按姓名和 PNR 双重查找和删除。等候替补客户名单使用链式队列，维护队头和队尾指针，严格先进先出，退票触发自动补位时从队头逐个处理。
七、文件结构与运行方式
项目包含四个文件：index.html（页面骨架，5个 Tab 分页）、css/style.css（航司主题样式）、js/data structures.js（基础数据结构，无业务逻辑）、js/airline system.js（核心业务层，含 Flight 和 AirlineSystem 类）、js/app.js（UI 交互层，DOM 操作和事件绑定）。JavaScript 文件必须按 data structures.js、airline system.js、app.js 的顺序加载。
运行方式极为简单：直接在浏览器中打开 index.html 即可，或使用任意 HTTP 服务器（如 python3 m http.server 8000）。数据自动保存在浏览器 localStorage 中，键名为 airline_v2_data。首次运行自动初始化测试数据和演示数据。
